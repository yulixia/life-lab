# 事项勋章规则

本文记录已确认的勋章累计、解锁与状态展示规则。勋章以事项为单位独立累计，不跨事项合并；它们奖励的是完成一次完整验证并复盘，而不是实践结果的好坏。

## 累计与解锁

- 勋章由历史周期和复盘结果推导，不手动发放，也不会因为开启下一轮、归档、恢复或长期终止而减少。
- “累计轮次”只统计状态为“已完成”且已经提交复盘的有效周期，不等同于事项实际开启过的周期数量，也不按所有历史周期的顺序直接编号。
- 一个周期只有同时满足以下条件，才计为一轮有效验证：周期内 7 个不同自然日都有每日记录，周期结算状态为“已完成”，且该周期已提交复盘。重复提交同一自然日的记录不会增加记录天数。
- 有效实践和未实践都属于每日记录；两者都可使当天计入 7 天完整记录。
- “已完结”表示自然结束时少于 7 天有记录；“已终止”表示提前结束。两者即使完成复盘，也不生成勋章、不占用累计轮次，也不会影响此前已经累计的有效轮次。
- 已完结或已终止之后可以开启下一周期。新周期只有达到“已完成”并提交复盘后，才作为下一轮有效验证加入累计；中间的已完结或已终止周期不占轮次序号。
- 长期事项只记录完成日期和备注，不产生新的实验勋章。

| 累计的有效已复盘周期 | 新解锁的勋章 | 已有勋章处理 |
| --- | --- | --- |
| 1 轮及以上 | 实验印记，每轮 1 枚 | 全部保留 |
| 3 轮及以上 | 持续验证章 | 原有实验印记保留 |
| 9 轮及以上 | 深度发现章 | 原有全部勋章保留 |
| 转为长期 | 长期同行外环，附着在当前最高等级勋章外 | 不改变等级或数量 |

勋章是里程碑“解锁”，不是把低等级勋章合成为高等级勋章。例：同一事项累计 9 轮有效已复盘周期时，仍保留 9 枚实验印记、持续验证章和深度发现章。

### 累计轮次示例

同一事项依次经历以下周期：

1. 第一个周期为“已完成，已复盘”：累计为第 1 轮有效验证，获得 1 枚实验印记。
2. 第二个周期为“已完结，已复盘”：累计仍为 1 轮，不获得勋章，也不占用第 2 轮。
3. 第三个周期为“已终止，已复盘”：累计仍为 1 轮，不获得勋章，也不占用第 2 轮。
4. 第四个周期为“已完成，已复盘”：累计增加为第 2 轮有效验证，再获得 1 枚实验印记。
5. 后续某个周期再次“已完成，已复盘”时，累计增加为第 3 轮，并解锁持续验证章。

因此，“第几轮”始终指第几次完成有效验证，而不是第几个被创建的周期。

## 状态展示

| 事项或周期状态 | 勋章展示 |
| --- | --- |
| 待探索 | 无本轮勋章；若有历史勋章，仅展示历史最高等级。 |
| 进行中，第 1 至 6 天 | 展示本轮解锁态。外圈 7 个区块对应周期内 7 个自然日，只有存在有效每日记录的日期才点亮；未记录日期保持未解锁。同时保留历史最高勋章。 |
| 进行中，第 7 天 | 7 天都有记录时，外圈完整显现、中心未点亮，等待本轮结算；记录不足 7 天时，外圈保持实际已记录天数对应的部分解锁状态。 |
| 已完成，待复盘 | 显示完整勋章预览，中心未激活；尚不计入累计。 |
| 已完成，已复盘 | 中心点亮，新增实验印记；达到第 3 或第 9 轮时同步解锁对应等级。 |
| 已完结，待复盘或已复盘 | 不显示可获得的本轮勋章；可保留低饱和的未完成实验轨迹，并展示本轮历史结果和既有勋章。该周期不计入累计轮次。 |
| 已终止，待复盘或已复盘 | 显示灰色实验轨迹，不生成本轮勋章；既有勋章保留。 |
| 已归档 | 静态展示既有最高等级与累计数量；归档仅来自“已完成，已复盘”。 |
| 长期进行 | 在事项实际达到的当前最高等级勋章外叠加长期同行外环；不改变勋章等级或累计轮次，不显示周期解锁进度。 |
| 长期已终止 | 保留实际当前等级勋章，长期同行外环使用低饱和暂停态。 |

## 展示位置与视觉层级

- 事项详情突出最高等级勋章，并展示累计，例如“实验印记 9 枚，持续验证章已解锁，深度发现章已解锁”。
- 今日页只展示进行中事项的本轮解锁态。
- 总库列表只展示最高等级的小型勋章，不堆叠全部勋章。
- 历史周期中，只有“已完成且已复盘”的周期标记为获得实验印记；已完结和已终止只显示周期结果。
- 同一套勋章以形状表达里程碑：实验印记为圆形、持续验证章为圆角六边形、深度发现章为八边形；模块差异由中心图案和主题色表达。

## 视觉资产与运行时呈现

首批勋章素材位于 `public/badges/`，索引文件为 `public/badges/manifest.json`。勋章采用“立体勋章位图 + 矢量状态层 + CSS 光影与动画”的组合方式：位图保留实体金属与珐琅质感，SVG 负责需要精确变化的业务状态，CSS 负责随页面环境变化的投影和解锁动效。

当前两枚勋章并排的效果图只作为视觉参考，不能直接放入系统。正式素材必须将每枚勋章单独导出，避免裁切、缩放和状态叠加时互相影响。

### 勋章素材制作与导出

- 每枚勋章使用独立的正方形透明画布，保持相同的画布尺寸、中心点、主体占比和安全边距；六枚勋章放入同一组件时不得出现大小或基线跳动。
- 勋章保持接近正面的轻微立体视角。金属高光、珐琅渐变、倒角、浮雕和勋章内部阴影直接保留在位图内，从而在不同页面尺寸下仍有稳定的实体质感。
- 页面外部投影和接触地面的椭圆阴影不得烘焙进勋章图片，由 CSS 统一生成，否则缩小后容易出现脏边，也无法适配深浅背景。
- 无需制作灰底或白底版本；所有勋章均保留透明通道。
- 母版使用高分辨率透明 PNG，建议 `2048 × 2048 px`；APP 运行时使用带透明通道的 WebP，并根据目标设备生成 1x、2x、3x 或等效响应式尺寸。
- 视觉材质统一为干净、明亮的银色金属与平滑不透明珐琅，厚度保持比最初厚版薄约 20%–25%；不得加入旧化、污渍、锈蚀、磨损或明显划痕。
- 理想自我使用蓝紫主题，中心表达“人物向理想与光靠近”；中心画框底部保持开放，人物可向下穿出内框约 10%–15%，但不得遮挡最外层七日进度环。
- 副业探索使用薄荷绿与青绿色主题，中心表达“沿路径探索并攀向目标”；路径和山体可延伸到内框底部，但不得侵入最外层七日进度环。
- 模块主题色沿用产品现有配色；等级主要通过外轮廓形状区分，不通过更换模块主色区分。

### 勋章本体，共 6 项

以下为运行时 WebP 文件；同名 PNG 仅作为高清母版保存，不计入运行时资产数量。

- `ideal-self-tier-1-experiment-mark.webp`：理想自我，圆形实验印记。
- `ideal-self-tier-2-continuous-validation.webp`：理想自我，圆角六边形持续验证章。
- `ideal-self-tier-3-deep-discovery.webp`：理想自我，切角八边形深度发现章。
- `side-hustle-tier-1-experiment-mark.webp`：副业探索，圆形实验印记。
- `side-hustle-tier-2-continuous-validation.webp`：副业探索，圆角六边形持续验证章。
- `side-hustle-tier-3-deep-discovery.webp`：副业探索，切角八边形深度发现章。

### 通用状态素材，共 3 项

- `progress-mask.svg`：七日进度层。代码根据周期内实际存在有效记录的日期点亮对应区块；待复盘时使用 7 段完整、中心未激活的状态。
- `long-term-ring.svg`：长期同行外环。叠加在事项实际达到的当前最高等级勋章外；长期终止时由代码降低外环饱和度和透明度，不制作另一张完整勋章。
- `terminated-experiment-trail.svg`：已终止事项的灰色实验轨迹；已完结周期可复用其低饱和未完成形态，不代表已获得勋章。

正式运行时视觉资产共 9 项，另有 1 个 `manifest.json` 索引文件。PNG 母版属于设计源文件，不进入运行时资产计数。若仓库中已存在按天拆分的 `*-progress-day-1.svg` 至 `*-progress-day-7.svg`、独立待复盘图或包含固定等级勋章的长期状态图，实施时应先迁移索引和引用，再移除重复状态资产。

### 页面合成层级

同一个勋章组件从下到上按以下顺序合成：

1. CSS 椭圆接触阴影。
2. 勋章本体 WebP。
3. 七日进度 `progress-mask.svg`。
4. 可选的长期同行 `long-term-ring.svg`。

已终止或已完结的未完成周期使用 `terminated-experiment-trail.svg` 表达，不把它误叠加成一枚已经获得的实体勋章。历史最高等级勋章和本轮实验轨迹应作为两个独立信息展示。

### 阴影实现

勋章使用 `filter: drop-shadow()`，不使用 `box-shadow`。`drop-shadow` 会沿透明图片的真实轮廓生成阴影，圆形、六边形和八边形都能保持自然的悬浮与厚度感；`box-shadow` 只会沿图片的矩形画布投影。

```css
.medal {
  position: relative;
  isolation: isolate;
}

.medal__image {
  display: block;
  width: 100%;
  height: auto;
  filter:
    drop-shadow(0 12px 14px rgba(79, 112, 132, 0.18))
    drop-shadow(0 3px 3px rgba(71, 94, 112, 0.12));
}

.medal::after {
  content: "";
  position: absolute;
  z-index: -1;
  left: 18%;
  right: 18%;
  bottom: 2%;
  height: 10%;
  border-radius: 50%;
  background: rgba(86, 111, 127, 0.16);
  filter: blur(12px);
}
```

以上数值是中尺寸勋章的基准。模块可以让阴影带有极轻的主题色倾向，但不得将阴影做成明显蓝色或绿色；小尺寸应降低模糊、距离和透明度，解锁大图可以增加一层非常克制的主题辉光。

### 建议显示尺寸

| 页面位置 | 勋章宽度 | 阴影强度 |
| --- | --- | --- |
| 总库列表或卡片 | 48–64 px | 很轻，仅保证与背景分离 |
| 今日实践卡 | 72–96 px | 中等，保留立体感 |
| 事项详情 | 140–180 px | 清晰展示材质与层次 |
| 解锁展示 | 220–280 px | 完整投影，可增加轻微主题辉光 |

实际布局可在区间内响应式调整，但同一页面同一层级必须保持统一尺寸。

### 解锁动画

解锁动效只在勋章首次被业务规则正式解锁时播放一次，不在普通页面刷新、列表复用或历史回看时反复播放。动效以轻微透视转正、缩放回弹和淡入为主，避免使用老虎机式闪烁或高频刺激。

```css
@keyframes medal-unlock {
  0% {
    transform: perspective(700px) rotateY(-10deg) scale(0.88);
    opacity: 0;
  }
  60% {
    transform: perspective(700px) rotateY(4deg) scale(1.04);
    opacity: 1;
  }
  100% {
    transform: perspective(700px) rotateY(0) scale(1);
  }
}

.medal--unlocked {
  animation: medal-unlock 700ms cubic-bezier(0.2, 0.8, 0.2, 1);
}

@media (prefers-reduced-motion: reduce) {
  .medal--unlocked {
    animation: none;
  }
}
```

实现时应由业务字段记录“本次解锁展示是否已经播放”，不能仅依赖 CSS 类或组件挂载状态，否则用户每次进入页面都会重复触发动效。
